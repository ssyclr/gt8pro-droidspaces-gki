# GT8 Pro Droidspaces GKI 内核

为真我 GT8 Pro（RMX5200）编译开启了 [Droidspaces](https://github.com/ravindu644/Droidspaces-OSS) 所需选项的 GKI 内核，要求 kABI 与原厂完全一致。刷机时只替换 boot 分区里的内核，其余分区全部保持原厂。

| 项 | 值 |
|---|---|
| 原厂内核 | `6.12.23-android16-5-gb2a876903b49-ab14541642-4k` |
| 源码 | AOSP `kernel/common` @ `b2a876903b49`（官方 GKI 构建 ab14541642） |
| 构建目标 | `//common:kernel_aarch64_dist`（4K 页） |

## 做了哪些改动

1. **源码完全按官方构建同步。** 从 ci.android.com 下载官方构建用的 `manifest_<构建号>.xml`。它把每个仓库（kleaf、clang r536225、rust 等）都固定在官方构建当时的提交上。
   `android16-6.12-2025-06` 分支已被 Google 改名为 `deprecated/android16-6.12-2025-06`，所以不能再按分支名 `repo init`。
2. **kABI 补丁** `patches/001.GKI-6.12-or-above-fix_sysvipc_kabi.patch`。原样取自 Droidspaces-OSS 的 `Documentation/resources/kernel-patches/GKI/kernel-6.12/`（取自提交 `21be5ba910da`）。
   - 它把 `CONFIG_SYSVIPC` 新增的 `sysvsem`/`sysvshm` 挪进 `task_struct` 里 `rt_priority` 和 `se` 之间的对齐空隙。原厂这里有 28 字节空隙，补丁用掉 24 字节，后面所有字段的偏移不变。
   - 再用 `__kabi_ignored` 让 gendwarfksyms 在 stable 模式（kleaf 设置了 `KBUILD_GENDWARFKSYMS_STABLE=1`）下不把它们算进符号 CRC。
3. **直接修改 `gki_defconfig`**（不用 fragment），选项清单见 [`config/droidspaces_options.txt`](config/droidspaces_options.txt)：`# CONFIG_X is not set` 改成 `=y`，已经是 `=y` 的不动，不存在的追加到末尾。脚本会检查：除清单选项和下面第 4 条外，`gki_defconfig` 里没有任何其他改动。
4. **信任原厂模块签名证书：** `CONFIG_SYSTEM_TRUSTED_KEYS="certs/stock_gki_module_signing.pem"`。
   - system_dlkm 里的 GKI 模块是用官方构建时生成的一次性密钥签名的。自编内核的密钥不同，如果不处理，这些模块会被当成未签名。6.12 的 GKI 模块保护随后会拒载 `rfkill.ko` 等模块，厂商的 `cfg80211`（Wi-Fi）、`btpower`（蓝牙）和 `nfc` 都依赖 `rfkill.ko`。
   - 证书从官方 Image 里提取（每次运行 workflow 都会自动提取）。它已验证能验过手机上全部 103 个 system_dlkm 模块。
   - 这一项只往内核里加了一张证书，不改变任何结构体或导出符号。
5. **`check_defconfig`：** 6.12 已不再读 `build.config.gki`，对应的开关是 `common/BUILD.bazel` 里 `kernel_aarch64` 的 `check_defconfig`。脚本先按原样跑 config 步骤，只有出现 `savedefconfig does not match` 时才把它设为 `"disabled"` 再重试。报告里会注明是否关闭过。

另外，构建加了 `--config=stamp`，这样 `uname -r` 里会带上源码提交号。

## 与 Droidspaces 文档不一样的地方

- **原厂本来就开着 `CONFIG_CFS_BANDWIDTH=y`**（Google 在 `gki_defconfig` 里开的）。这里保持原样：关掉它和打开它一样会破坏 ABI。所以 Droidspaces 的 `--cpus` 可以用。`CONFIG_CGROUP_PIDS` 不开，`--pids-limit` 不可用。
- **`CONFIG_NETFILTER_XT_TARGET_REJECT` 在这个源码树的 Kconfig 里不存在**，按文档加上后会被 Kconfig 丢掉，报告里标为「➖」。iptables 的 REJECT 由原厂已开启的 `IP_NF_TARGET_REJECT` / `IP6_NF_TARGET_REJECT` 提供。

## 红线（脚本层面已防护）

- 不开 `CFS_BANDWIDTH`、`CGROUP_PIDS`，也不改动它们的原厂状态。
- 不开文档清单以外的选项。唯一例外是第 4 条的 `SYSTEM_TRUSTED_KEYS`：它是证书路径，不是功能开关，已获批准。
- 不关 `CONFIG_MODVERSIONS`，不强制加载模块。
- 只刷 `boot`。

## 运行

GitHub → Actions → **Build Droidspaces GKI kernel** → Run workflow。

| 输入 | 说明 |
|---|---|
| `build_id` | 官方 GKI 构建号，即 `adb shell uname -r` 里 `-ab` 后面的数字 |
| `skip_options` | 排查用：本次不开的「推荐」选项，空格分隔，不带 `CONFIG_` |
| `build_stock` | 同时编一份未改动的内核作对照（默认开）。它应该和官方构建逐个符号一致，用来证明构建环境没问题 |

各个 job：

1. **baseline**：下载官方 manifest、`vmlinux.symvers`、`.config`，从官方 Image 提取 BTF 和模块签名证书。
2. **build**（matrix：`stock` / `droidspaces`）：清理 runner 磁盘，按官方 manifest 同步源码，打补丁、改配置（仅 droidspaces），然后构建。
3. **report**：生成 ABI 自检报告，不通过时 job 失败。

产物（Artifacts）：

- `droidspaces`：`Image`、`Image.lz4`、`Image.gz`、`config`（用 `extract-ikconfig` 从 Image 提取的最终配置）、`vmlinux.symvers`、`source.diff`，等等。
- `abi-report`：`abi-report.md` / `abi-report.json`。
- `stock`、`baseline`、`logs-*`。

## ABI 自检（刷机前必须通过）

`abi-report.md` 包含：

- **符号**：官方 → droidspaces 的 `vmlinux.symvers` 对比。已有符号的 CRC 变化必须为 0；不能有符号被删除；导出类型或命名空间也不能变（比如从 `EXPORT_SYMBOL` 变成 `_GPL`）。新增符号可以接受。
- **配置**：清单里每个选项是否真的是 `=y`（依赖不满足时会被静默丢掉）、两个禁止项是否与原厂一致、`MODVERSIONS` 是否开启，以及全部配置差异。
- **证书**：原厂模块签名证书是否已打进新 Image。
- **结构体布局**：用 BTF 对比内核里所有具名结构体。`task_struct` 应该显示为「只在空隙里新增成员」；如果有任何已有成员移位，会单独列出，需要人工审查。

如果不通过，用 `skip_options` 每次去掉一个「推荐」选项重新运行，以此定位是哪个选项导致的。

## 刷机（手机上用 KernelSU 自带的 magiskboot）

```bash
adb shell getprop ro.boot.slot_suffix        # 例如 _a
adb shell su -c "dd if=/dev/block/by-name/boot_a of=/data/local/tmp/boot_stock.img"
adb shell su -c "dd if=/dev/block/by-name/init_boot_a of=/data/local/tmp/init_boot_stock.img"
adb pull /data/local/tmp/boot_stock.img
adb pull /data/local/tmp/init_boot_stock.img      # 两个原厂备份都要在电脑上保存好
adb push Image /data/local/tmp/
adb shell su -c "cd /data/local/tmp && mkdir -p repack && cd repack && \
  /data/adb/ksu/bin/magiskboot unpack ../boot_stock.img && \
  cp ../Image kernel && \
  /data/adb/ksu/bin/magiskboot repack ../boot_stock.img ../new-boot.img"
adb pull /data/local/tmp/new-boot.img
```

注意 `unpack` 输出的 `KERNEL_FMT`。`repack` 会按原格式自动压缩；如果没有自动压缩，就改用产物里对应格式的 `Image.lz4` 或 `Image.gz`。

先临时启动，不写分区：

```bash
adb reboot bootloader
fastboot boot new-boot.img
```

确认没问题后再正式刷入：`fastboot flash boot new-boot.img`，然后 `fastboot reboot`。

## 刷入后验证

```bash
adb shell uname -a
adb shell su -c "zcat /proc/config.gz" | grep -E "SYSVIPC|POSIX_MQUEUE|IPC_NS|PID_NS|DEVTMPFS|USER_NS|MACVLAN"
adb shell su -c "dmesg" | grep -iE "disagrees about version|Unknown symbol|module verification|exports protected"
adb shell su -c "grep 'Build time autogenerated kernel key' /proc/keys"   # 应有两条：新内核自己的 + 原厂的
```

- dmesg 里不应有任何符号版本或模块签名相关的报错。
- KernelSU 管理器应显示「工作中」；如果掉了，在管理器里重新安装 LKM。
- Wi-Fi、蓝牙、NFC、蜂窝数据、相机、指纹、充电都要正常。
- 最后在 Droidspaces App 里跑「设置 → 要求 → 检查要求」。

## 回滚

无限重启时，按住电源键 + 音量下进入 fastboot：

```bash
fastboot flash boot boot_stock.img
```

init_boot 没有被改动，KernelSU 不受影响。

## 系统更新后重新编译

OTA 会把 boot 换回新的原厂内核，同时更新 system_dlkm。

1. `adb shell uname -r`，记下新的构建号（`-ab` 后面的数字）。
2. 用新构建号运行 workflow。证书、manifest、ABI 基准都会自动从新构建获取。核对报告里原厂证书的 SKID，应与 `/proc/keys` 里那把 key 的 ID 一致。
3. 如果补丁打不上（dry-run 失败），workflow 会停下，需要先更新补丁。

**不要把旧构建号编出的内核刷到新系统上。** 证书、CRC 基准都和构建号绑定。
